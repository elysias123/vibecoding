# 后端基础参考

此参考用于跨领域后端工作：API 设计、数据库模式、身份验证或授权。请与技术栈专用参考一起使用。

## API 设计

- 使用复数资源名词和 HTTP 动词：使用 `/users`，而不是 `/user`。
- 返回一致的错误结构：`{ "error": { "code": "...", "message": "..." } }`，并使用合适的 HTTP 状态码。
- 大型数据集优先使用游标分页；小型且稳定的数据集可使用偏移分页。
- 公共 API 使用 `/v1/` 路径版本控制；内部服务使用请求头版本控制。
- 在边界验证所有输入；绝不信任客户端数据。
- 为公共端点设置速率和请求大小限制。

## 数据库模式

- 业务逻辑使用 ORM 或查询构建器；仅在性能关键路径使用原始 SQL。
- 每次架构变更都使用迁移；绝不手动修改生产架构。
- 为外键和高频查询列建立索引，但不要为写入密集型表过度建立索引。
- 对必须原子完成的多步写入使用事务。
- 生产环境使用连接池。

## 身份验证与授权

- 使用 bcrypt、argon2 或 scrypt 对密码哈希；绝不存储明文、MD5 或 SHA 哈希。
- 无状态 API 使用 JWT；服务端渲染应用使用带 CSRF 防护的会话 Cookie。
- 对每个受保护操作在服务端验证权限。
- 使用短期访问令牌（15 到 30 分钟）和刷新令牌。
- 将机密存储在环境变量或机密管理器中，绝不放入源代码。

## 可观测性

- 输出带请求 ID 的结构化 JSON 日志。
- 为负载均衡器提供 `/health` 或 `/healthz` 端点。
- 跟踪请求延迟、错误率和数据库查询耗时。
