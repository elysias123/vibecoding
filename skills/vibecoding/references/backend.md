# 后端基础参考

此参考用于跨领域后端工作：API 设计、数据库模式、身份验证或授权。请与技术栈专用参考一起使用。

## 文件架构示例

按业务职责组织目录的示例：

```text
backend/
├─ api/          # 对外接口
├─ business/     # 业务模块和业务逻辑
├─ database/     # 数据库、缓存、文件存储和数据结构变更
├─ config/       # 配置
└─ tests/        # 测试代码
```
> 目录和名称仅作示例，不绑定语言或框架；既有项目沿用现有结构，不为符合示例移动文件。

- 出现职责混杂、测试困难或实际替换需求时，在必要边界进行分层或解耦；小项目可合并目录，不默认增加接口、包装层或拆分目录。
- 架构记录优先沿用已有文档，仅在实际架构变化时更新相关内容，不默认额外写入 `AGENTS.md`。

## API 设计

- 使用复数资源名词和 HTTP 动词：使用 `/users`，而不是 `/user`。
- 返回一致的错误结构：`{ "error": { "code": "...", "message": "..." } }`，并使用合适的 HTTP 状态码。
- 大型数据集优先使用游标分页；小型且稳定的数据集可使用偏移分页。
- 公共 API 使用 `/v1/` 路径版本控制；内部服务使用请求头版本控制。
- 在边界验证所有输入；绝不信任客户端数据。
- 为公共端点设置速率和请求大小限制。

## 数据库模式

- 优先沿用现有数据库访问方式；ORM、查询构建器和参数化 SQL 按任务需求选择，不为统一选型引入依赖或迁移现有实现。
- 每次架构变更都使用迁移；绝不手动修改生产架构。
- 为外键和高频查询列建立索引，但不要为写入密集型表过度建立索引。
- 对必须原子完成的多步写入使用事务。
- 生产环境使用连接池。
